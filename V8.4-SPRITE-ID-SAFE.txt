TAMAPOKE MORETRO V8.4 - SPRITE ID SAFE

CAUSE EXACTE DU BUG GOELISE :
Le chargeur PmdMon utilisait uint8_t pour le numéro Pokédex.
278 ne tient pas dans 8 bits et devenait 22.
#278 GOELISE chargeait donc /mons/p022.bin = RAPASDEPIC.

CORRECTIONS :
- PmdMon::load : uint16_t
- SdMon::load : uint16_t
- contrôle 1..386 avant ouverture SD
- AudioEvent.value : uint16_t
- playSpeciesChirp : uint16_t
- suppression du cast uint8_t des cris
- correction d'une boucle nextDexGoal qui dépassait le tableau
- récompenses Pokédex adaptées jusqu'à 251 et 386
- audit automatique de 386 normaux + 386 shiny
- audit TPK2 de chaque fichier
- audit thumbs.bin = 386
- audit anti-régression des types uint8_t Dex

Le dépôt PMDCollab utilise bien les numéros du Pokédex pour ses espèces ;
le problème observé venait du wrap 8 bits côté firmware.
